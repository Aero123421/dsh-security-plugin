# DSH Security

[English](README.md)

DSH Security は、[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH 0.2.x）用のセキュリティレビュー・プラグインです。DSH のサイドバーに「セキュリティ」ページが追加されます。スキャンでは、まずプロジェクトの読み取り専用スナップショットに組み込みの解析ツールをかけます。続いて、DSH に接続済みのモデルを使う AI レビュアーが、攻撃者が実際に悪用できる問題を探します。AI の主張には、根拠となるコードの正確な引用が必要です。プラグインは引用をすべてスナップショットと照合し、照合できない主張は捨てます。残った問題には、別の検証役が「本当は防がれているのではないか」という立場で反証を試みます。結果は手元のコンピューターだけに保存され、Markdown・JSON・SARIF で書き出せます。

## できること

- **決まった手順で動く解析ツール**: 秘密情報の検出 25 ルール（伏せ字処理も兼ねています）、JavaScript/TypeScript・Python・Dockerfile・Compose・Kubernetes 向けのパターンルール 52 個、エンドポイント（外部からの入口）の抽出（Express、Fastify、Koa、Hono、NestJS、Next.js、Flask、FastAPI、Django）、npm・PyPI・Go・Cargo のロックファイル解析。オプションで OSV.dev への脆弱性照会と、インストール済みなら Gitleaks・OSV-Scanner・Semgrep も使います。詳しくは [docs/analyzers.md](docs/analyzers.md)。
- **読み取り専用のマルチエージェント・レビュー**: プランナーが脅威を整理し、ハンターがエンドポイント・ルールの検出箇所・機密性の高いファイル・プランナーの仮説を調べます。リサーチモードでは、組み合わせ分析役が複数の弱点をつなげた攻撃も探します。AI が使えるのはスナップショット内のファイルを一覧・読み取り・検索するツールだけです。シェル、ネットワーク、ファイルの書き込みは使えません。
- **ホストによる根拠の照合**: AI が引用したコードは、伏せ字処理済みのスナップショットと 1 件ずつ照合されます。引用したコードが実在する場合だけ「照合済み」になります。照合済みの手順が 1 つもない問題は取り下げられ、その件数は「調べた範囲」に表示されます。
- **独立した検証役**: ディープとリサーチでは、ハンターの推論を見ていない別の AI が、主張と照合済みのコードだけを見て反証を試みます。「問題なし」と判断するには防御しているコードの引用が、「本当の問題」と判断するには照合済みのコードが必要です。
- **レポートと事後対応**: あなたの判断（誤検知・リスク受け入れなど）は同じプロジェクトの次回以降のスキャンに引き継がれます。「DSH のチャットで修正する」で修正用の指示文を通常の DSH チャットに渡せます。レポートは Markdown（英語・日本語・中国語）、JSON、SARIF 2.1.0（コードスキャン用ダッシュボード向け）で書き出せます。

## やらないこと

- 攻撃の実行、コードの実行、依存パッケージのインストール、テストの実行はしません。
- ネットワーク・ホスト・稼働中のサービスはスキャンしません。読むのはソースファイルだけです。
- **「問題 0 件」は「安全」という意味ではありません。** スキャンが報告するのは、予算の範囲内で見つけられ、根拠を示せた問題だけです。何を調べていないかは「調べた範囲」で確認してください。
- 専門家によるセキュリティ診断やペネトレーションテストの代わりにはなりません。結果は選んだモデルに大きく左右され、誤検知も見逃しも起こります。

## はじめかた

1. **インストール**: DSH の Web UI で「プラグイン → プラグインを追加」を開き、次を入力します。

   ```text
   github:Aero123421/dsh-security-plugin#v0.2.1
   ```

   ターミナルから入れる場合（ここでは `web` プロファイル）:

   ```sh
   dsh plugin --profile web add -w github:Aero123421/dsh-security-plugin#v0.2.1
   ```

   `#` の後ろには、入れたい[リリース](https://github.com/Aero123421/dsh-security-plugin/releases)のタグを指定します。タグを省くと、未リリースの `main` ブランチが入ります。各リリースにはビルド済みの `dsh-security-plugin-X.Y.Z.tgz` と `SHA256SUMS` も添付しており、その URL を同じ場所に入れても導入できます。npm には公開していません。有効化し、再起動を求められたら DSH を再起動してください。更新するときは、新しいタグで同じように追加します。動いている版は「設定」タブで確認できます。読み込まれたかどうかは、`dsh --profile web --dump-config` の出力に `# == dsh-security-plugin` というレイヤーがあるかで確認できます。
2. **セキュリティを開く**: サイドバーの「セキュリティ」を開き、プロジェクトを選びます。「プロジェクトフォルダーを追加…」（利用できる場合）で、別のフォルダーを DSH のプロジェクト一覧に登録し、スキャン対象として選べます。
3. **モデルを選ぶ**: ページの「設定」タブ →「AI モデル」で選びます。「デフォルト」を 1 つ選べば十分で、役割（プランナー・ハンター・検証役・組み合わせ分析役）ごとに別のモデルも指定できます。スキャンには、ハンター用のモデル（個別指定またはデフォルト）が最低限必要です。
4. **新しいスキャン**:「ディープ」を選び、見積もり（ファイル数、エンドポイント数、AI レビューの作業数、トークン数の目安）を確認してから、同意のチェックボックスにチェックを入れます。この同意はセキュリティの設定に保存され、オフにするまで以降のスキャンにも適用されます。
5. **スキャンを開始**:「概要」タブで進み具合・動いているレビュアー・トークン使用量を確認できます。スキャンは DSH のホスト側で動くので、タブを閉じても止まりません。一時停止・再開・中止も同じページから操作できます。DSH の停止で「中断」になったスキャンは、あとから再開できます。

## 結果の読み方

検出結果には、互いに独立した 2 つの評価があります。「緊急」でも「可能性あり」のままのことがあります。

| 重大度（本当なら影響はどれくらいか） | 確かさ（どこまで裏付けられたか） | 結論 |
| --- | --- | --- |
| **緊急**: ログインなしで乗っ取り、またはほぼ全データが漏れる | **コードで確認済み**（`strong_static_evidence`）: 照合済みのコードで攻撃経路を示せ、独立レビューでも防御が見つからなかった。確度の高いハードコードされた秘密情報も最初からここに入ります | 確認済み |
| **高**: 他のユーザーやテナントのデータに触れる、またはログインなしで機密データに届く | **可能性あり**（`potential`）: ルールの検出や AI の仮説で、まだ誰も確かめていない | 要確認 |
| **中**: 実害はあるが限定的、または前提条件が重い | **判断保留**（`inconclusive`）: リポジトリの外の事情（デプロイ設定など）次第で決まる | 要確認 |
| **低**: 影響が小さい、または起こりにくい | **問題なしと判断**（`refuted`）: 攻撃を防ぐコードが照合済みの引用つきで示された | 除外済み |
| **情報**: 注目すべきだが悪用はできない | **再現済み**（`proven_dynamic`）: 実際に動かして確かめる検証用。コードを読むだけのスキャンでは付きません | 確認済み |

- **結論**は確かさから自動で決まるので、2 つが食い違うことはありません。「概要」の未対応件数には、除外済みの問題と、あなたが対応不要と判断した問題は含まれません。
- **あなたの判断**（未対応・リスクを受け入れる・誤検知・修正済み）は、プロジェクトごと・問題の指紋（フィンガープリント）ごとに保存され、次回以降のスキャンにも引き継がれます。指紋には行番号を含めないので、コードが移動しても判断は消えません。前回の完了済みスキャンになかった問題には **新規** が付きます。
- 引用された各手順には照合結果が表示されます:「引用を確認済み」「確認済み（行を補正）」（同じファイルの別の行で 1 か所だけ見つかった）「確認できず」。
- **DSH のチャットで修正する** を押すと、同じプロジェクトで新しい DSH チャットが開き、修正用の指示文（問題の内容・照合済みのコード・修正の方針）が入力欄に入ります。送信する前に内容を確認してください。修正するのはいつものコーディングエージェントで、権限もいつも通りです。このプラグイン自体がコードを書き換えることはありません。「修正用の指示文をコピー」でも同じ文面をコピーできます。
- 直したら **クイックスキャンで再確認** を押して、問題が消えたかを確かめましょう。

## スキャンモード

| | クイック | ディープ（標準） | リサーチ |
| --- | --- | --- | --- |
| 脅威の整理（プランナー） | なし | あり（仮説は最大 8 個） | あり（仮説は最大 16 個） |
| AI による調査 | 中以上のルール検出箇所をファイルごとに確認 | エンドポイント、ルールの検出箇所、プランナーの仮説、機密性の高いファイル（最大 6 個） | ディープと同じ |
| 独立レビュー（検証役） | なし | 「再確認する深刻度」（標準は中）以上 | 低以上 |
| 組み合わせ分析 | なし | なし | あり |
| **標準の予算**: AI リクエスト数 | 40 | 300 | 1,200 |
| トークン数 | 400,000 | 3,000,000 | 12,000,000 |
| 時間（分） | 10 | 60 | 240 |
| レビュアー 1 人あたりのリクエスト数 | 12 | 24 | 40 |
| レビュー作業数 | 6 | 40 | 150 |

クイックでは、AI はルールの検出箇所が本物かどうかを確かめるだけで、認可漏れのようなロジックの欠陥は探しません。組み込みルールが何も見つけなければ、AI の作業は 1 つも行われません。

予算のどれか 1 つに達すると、スキャンは新しい作業を始めずに終了し、調べきれなかった部分を一覧にします。予算はモードごとに設定で変更でき、管理者が決めた上限で頭打ちになります（[docs/configuration.md](docs/configuration.md)）。各スキャンは、開始時点の設定・モデル・予算をそのまま使い続けます。ただしプライバシーの設定 2 つは例外です。「コードを AI モデルに送る」をオフにすると、待機中・一時停止中・実行中のスキャンも AI レビューをやめ、組み込みの解析ツールの結果で完了します。「送信しないファイル」に追加したパターンは、スキャンの開始時と再開時に反映されます。時間の上限は締め切りとして働き、過ぎた時点で実行中のリクエストも止めます。

## プライバシーとデータの流れ

| 送るもの | 送信先 | 送るタイミング |
| --- | --- | --- |
| AI レビュアーが読んだコードの一部と作業の指示（ファイルパス、エンドポイント一覧、ルール検出箇所の抜粋） | 役割ごとに選んだモデルのプロバイダー（DSH の LLM レジストリと DSH に登録済みの認証情報を経由） | AI を使うスキャンで、かつ「コードを AI モデルに送る」を許可したときだけ |
| ロックファイルにあるパッケージのエコシステム・名前・確定バージョン | `https://api.osv.dev`（または管理者が指定したミラー） | 「既知の脆弱性をオンラインで照会する（OSV）」がオンのときだけ（標準はオフ） |
| 固定済みの Gitleaks / OSV-Scanner のダウンロード要求 | `toolkit.lock.json` に書かれた GitHub のリリース URL | 「インストール」を押し、ツールのライセンスに同意したときだけ |
| それ以外 | なし | テレメトリ、利用状況の収集、更新確認は一切ありません |

モデルに届く前に、次の処理が入ります。

- スキャナーが見つけた秘密情報は、すべての抜粋で `[REDACTED:<ルールID>]` に置き換えられます。ツールの出力全体にも、もう一度パターンによる伏せ字処理をかけます。秘密情報の値そのものは保存せず、検出結果には先頭数文字だけを残した伏せ字表示を記録します。
- **送信しないファイル** は、AI のツール（一覧・読み取り・検索・引用）では一切返しません。組み込みのリスト: `.env` と `.env.*`（`.example`・`.sample`・`.template` は除く）、秘密鍵と証明書、`.npmrc`、`.pypirc`、`.netrc`、`.git-credentials`、`.pgpass`、`.htpasswd`、AWS・Docker・Kubernetes のクライアント認証情報（`.aws/credentials`、`.aws/config`、`.docker/config.json`、`.kube/config`、`kubeconfig`）、サービスアカウントの JSON、`secrets.y(a)ml`、Terraform の state と `*.tfvars`。設定の「送信しないファイル」で追加できます。AI への作業の指示文も同じ扱いで、こうしたファイルでのルール検出はパスとルール ID だけを伝え、そこで定義・マウントされたルートは一覧に含めません。
- プロジェクトの絶対パスは、すべてのツール出力で伏せられます。
- 外部の解析ツールはこのコンピューター上で動きます。OSV-Scanner は、OSV 照会がオフならオフラインで動きます。Semgrep はローカルのルールだけを使い、利用統計の送信はオフにして実行します。スキャン対象のプロジェクト側にあるこれらのツールの除外設定（`.gitleaks.toml`、`osv-scanner.toml`、`nosemgrep` コメント）は使いません。ただし Semgrep は `.semgrepignore` を読みます。

伏せ字処理はパターンに基づきます。ルールが知らない形式の認証情報はモデルに届く可能性があるので、そうした値を含むファイルは「送信しないファイル」に追加してください。

データは `$DSH_HOME/security/`（標準では `~/.dsh/security/`）に保存されます。`security.db` にはスキャン・検出結果・根拠・設定・判断、それに AI とのやり取りの記録（オフにしない限り）が入ります。`toolkit/` には導入した解析ツールが入ります。Linux と macOS では、ディレクトリは `0700`、データベースは `0600` の権限で作られます。90 日より古いスキャンは DSH の起動時に削除されます（日数は変更可能）。

## 設定

利用者の設定は、セキュリティページの「設定」タブ（DSH の設定 → セキュリティ からも開けます）で変更します。管理者は、プロファイルの `cordis.patch.yml` で上限やパスを決められます。たとえば、別の端末から開いたページではコード送信をオンにできないようにする、OSV の照会先をミラーにする、といった設定です。前者はブラウザーで開いたページに対する方針で、アクセス制御ではありません（DSH の認証情報を持つ人は DSH の管理者そのものです）。すべての項目・標準値・記述例は [docs/configuration.md](docs/configuration.md) にあります。

## 動作要件と互換性

- **DSH** `>=0.2.1-alpha.2 <0.3.0-0`、Web UI（`dsh.client.platform: web`）。DSH は任意の peer dependency で、このパッケージが DSH をインストールすることはありません。
- **Node.js** `^22.19.0 || >=24.0.0`（保存に組み込みの `node:sqlite` を使います）。
- DSH にモデルのプロバイダーが 1 つ以上接続されていて、そのモデルがツール呼び出しに対応していること。
- Linux・macOS・Windows。`@ast-grep/napi` は主なプラットフォーム向けのビルド済みバイナリを持つ任意の依存です。入っていなくても組み込みのトークナイザーで動きますが、精度は少し下がります。Python の構文木には `@ast-grep/lang-python` も必要で、これは自動ではインストールされません。
- 任意の外部ツール: Gitleaks 8.19 以降（それより古い版では従来の `detect` コマンドで動かします）、OSV-Scanner v2（v1 も可）、ローカルのルールファイルを用意した Semgrep。

## 困ったときは

| 症状 | 原因と対処 |
| --- | --- |
| 「スキャンに使う AI モデルがまだ設定されていません」（`security/no-model`） | 設定 →「AI モデル」でデフォルトかハンターのモデルを選んでください。選んでいたプロバイダーが DSH から外された場合も同じエラーになります。 |
| 「スキャンするには、伏せ字処理したコードを AI モデルに送る許可が必要です」（`security/consent-required`） | 新しいスキャンの画面で同意のチェックボックスにチェックを入れるか、設定 → プライバシーと安全 →「コードを AI モデルに送る」をオンにしてください。 |
| 「この操作は、管理者の設定により DSH が動いているコンピューター本体からしか行えません」（`security/forbidden-remote`） | 別の端末（またはリバースプロキシ経由）でページを開いていて、管理者が `allowRemoteHighRiskSettings: false` にしています。ホストのコンピューターで直接オンにしてください。オフにする操作はどこからでもできます。 |
| 「ほかのスキャンが実行中です」（`security/busy`） | 1 つのプロジェクトで待機中・実行中にできるスキャンは 1 つだけなので、新しいスキャンは作られていません。今のスキャンが終わるのを待つか、「概要」で一時停止・中止してから、もう一度開始してください。 |
| スキャンが「順番待ち」のまま | 全プロジェクト合計で同時に動くのは `maxConcurrentScans`（標準 1）件までで、残りは順番待ちになります。 |
| 「調べた範囲」→「実行できなかったチェック」に ast-grep が「native module unavailable on this platform」と出る | この OS・CPU・libc 向けの `@ast-grep/napi` のバイナリがないか、インストール時に任意の依存が省かれました。スキャンは組み込みのパーサーで続行します。任意の依存も含めて入れ直すと復活します。`disableAstGrep: true` にしている場合は想定どおりです。 |
| DSH のログに `ExperimentalWarning: SQLite is an experimental feature` | Node 22 が `node:sqlite` について出す警告で、害はありません。消したい場合は `NODE_OPTIONS=--disable-warning=ExperimentalWarning` を付けて DSH を起動してください。 |
| ホストのログに「this DSH build has no exact-route support; the Security page is unavailable」 | DSH が古すぎます。対応範囲のバージョンを使ってください。 |
| 「引用したコードがプロジェクト内で見つからなかったため、問題の候補 N 件を取り下げました」が多い | モデルが実在しないコードを引用しています。ハンターにより強いモデルを使ってください。 |
| お知らせに「The model provider refused some review requests」 | プロバイダーのコンテンツポリシーで要求が拒否されました。その作業は「未レビュー」として記録され、別のモデルに自動で切り替えることはしません。 |
| 解析ツールに「インストール」ボタンがなく「The managed download is not pinned yet」と出る | このリリースには、お使いのプラットフォーム向けのチェックサムがないため、ダウンロードしません。表示される案内に従って自分でインストールし、`PATH` に置いてください。自動で検出されます。 |
| Semgrep が「no local semgrep rules were configured」で使えない | `semgrepConfig` にルールファイルかディレクトリの絶対パスを設定してください。レジストリのルールは取得しません。 |
| OSV-Scanner が「offline mode is on and no local osv-scanner database was found」で使えない | OSV 照会がオフなので、OSV-Scanner はローカルのデータベースしか使えません。OSV 照会をオンにするか、OSV-Scanner でデータベースを取得してください。 |
| スキャンが「中断」になった | スキャン中に DSH が停止しました。「再開」を押してください。終わった AI の作業はやり直しません。 |

## 開発

```sh
pnpm install              # Node 22.19 以上または 24 以上、pnpm 10.28（packageManager を参照）
pnpm build                # lib/index.js（ホスト側）と lib/client.js（ブラウザー側）
pnpm lint                 # Biome
pnpm typecheck
pnpm test                 # Vitest: host（node）と client（happy-dom）の 2 プロジェクト
pnpm check                # 上のすべて + パッケージの検証
pnpm check:dsh            # 最新の DSH alpha（ネットワークが必要）: peer 範囲、型、捨てプロファイルでの起動
```

- 手元のチェックアウトを DSH で試すには、そのディレクトリで `pnpm install && pnpm build` を実行してから `dsh plugin --profile web add /絶対パス/チェックアウト` を実行します。変更したら再ビルド（`pnpm build:watch`）して DSH を再起動してください。
- API キーなしのエンドツーエンド確認には、`tests/e2e/scripted-llm/` の決定的なテスト用モデルを使います。手順は [docs/e2e-testing.md](docs/e2e-testing.md)。
- `pnpm bench` は、意図的に脆弱にした `tests/fixtures/apps/` のアプリをオフラインでスキャン（組み込みの解析ツールと、AI 部分はテスト用モデル）し、正解データと突き合わせて採点します。[docs/benchmark.md](docs/benchmark.md) を参照してください。
- 設計: [docs/architecture.md](docs/architecture.md)。プラグイン自体の脅威モデル: [docs/security-model.md](docs/security-model.md)。リリース手順: [docs/releasing.md](docs/releasing.md)。

貢献は歓迎します。まず [CONTRIBUTING.md](CONTRIBUTING.md) をお読みください。プラグイン自体の脆弱性は、[SECURITY.md](SECURITY.md) の手順で非公開で報告してください。
